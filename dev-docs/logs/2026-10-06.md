## 2026-10-06 — Decode deposit memos with cosmjs instead of byte scanning

**Problem.** The memo is the deposit allocation key (which user, fine, etc.),
but it was extracted by two hand-rolled base64/protobuf byte scanners
(`RPCTransactionVerification.parseRPCTransaction`, `UnifiedWalletService.parseMemo`)
that guessed a `0x12` field near the amount and could latch onto fee/gas numbers
or `authInfoBytes`.

**Changes.**

- New `src/utils/txMemo.ts`: `decodeMemo(base64Tx)` uses cosmjs `decodeTxRaw`
  (already a dependency) and returns `body.memo`, or `undefined` on decode
  failure (logged at `warn`).
- `RPCTransactionVerification.parseRPCTransaction` and the automated listener's
  two call sites now use `decodeMemo`; the two scanners (~190 lines) are deleted.
  `parseUserId` is unchanged.
- Behaviour is the same on failure — no memo → `verifyDeposit` invalid /
  listener routes to `UNCLAIMED` — but the memo is now the exact signed value.
- `cosmjs-types` added to `devDependencies` (test-only encoding helper).

**Doc-Impact.** README architecture bullet updated. `chat-explorer-integration.md`
unchanged.

**Verification.** `bun run lint`, `bunx tsc --noEmit`, `bun run test` (244
passing) green; boundary tests cover `verifyDeposit` with a real memo TxRaw.

## 2026-10-06 — Canonical `jailings` table + jailing-id memos; archive endpoints

**Jailings.** New `jailings` table is the source of truth for a jail: unique
alphanumeric `jailing_id` (leading letter, case-insensitive), `paid`, unique
`payment_tx`, and `muted_until`. `jail_events` stays the audit log. Migration 014
creates and backfills it. `JailService` gained `getActiveJailing`,
`getJailingByPublicId`, `payJailing` (atomic, tx-unique, expiry-gated), and
`releaseJailingTelegram`; `jailUser` now returns the id.

**Payment flow.** `/paybail` and `/bailhelp` show the Jailing ID and require it in
the tx memo. `/verifybail <txhash>` reads the memo → jailing → verifies status,
exact amount to the treasury, then releases. The automated deposit listener
detects bail memos exclusively (never credits them as deposits) and releases the
user; it never falls through on failure. A jailing-id memo can no longer be
mis-parsed as a user id (`parseUserId` now requires an all-numeric memo).

**No-memo deposits.** A memo-less transfer is attributed to the sender's user id
only when the address maps to exactly one user; otherwise it goes to UNCLAIMED.
Memos still work (including crediting another user).

**Endpoints / load.** Defaults are now `https://rpc-archive.junonetwork.io` and
`https://lcd-archive.junonetwork.io`. The listener polls on
`intervals.depositCheckMs` (default 90s) and `tx_search` uses `order_by=desc` with
an early stop at the last processed height, so it no longer re-scans history.

**Verification.** `bun run lint`, `bunx tsc --noEmit`, `bun run test` (251
passing) green.
