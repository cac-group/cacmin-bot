## 2026-09-10 — Fix rate-limit warning pileup under concurrent updates

**Problem.** A user spamming messages produced a new "don't have enough tendie
points" warning for every message, with no deletions happening.

**Root cause.** Telegraf processes each update batch concurrently
(`Promise.all` in `polling.js`), so all messages in a burst run the filter in
parallel. The old `prepareResponse` checked for a previous warning, then
`ctx.reply` awaited before `recordResponse` stored it — leaving a window where
every concurrent handler saw "no previous warning" and posted one. The
rate-limit mute row had the same visibility gap but only gates later batches.

**Change.** `prepareResponse` now claims its slot synchronously (before any
`await`) and returns `false` when a fresh response is already visible or
in-flight; `messageFilter.ts` and `restrictionService.ts` skip sending when it
returns `false`. Net effect: one warning per user per 2-minute window, with
sequential replacements still deleting the previous message.

**Tests.** Added `tests/unit/autoDelete.test.ts` (concurrent skip, replacement,
post-record reuse). Full suite: 152 passing; lint clean on touched files.

**Follow-up.** If warnings still recur every ~2 minutes in production, the
likely cause is `restrictChatMember` failing (bot lacking restrict rights),
which skips the `user_rate_limit_mutes` insert — consider inserting the mute row
before the Telegram restriction call as a degraded-mode fix.
