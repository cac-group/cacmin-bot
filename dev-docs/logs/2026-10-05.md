## 2026-10-05 — Consolidate fines/bail help under User → "Jailed?" and fix `[object Object]`

**Problem.** `/help` exposed a top-level "Payments" category split into "Fines"
and "Bail", though a fine and a bail are the same thing to a user: JUNO owed to
be released. Separately, `/paybail` (and three sibling messages) printed
`[object Object]` where the payment address/tx hash should be.

**Root cause of `[object Object]`.** Telegraf's `code()`/`bold()` return
`FmtString` objects that only render correctly when passed through `fmt` or
another `FmtString`. `jail.ts` interpolated `code(...)` into a plain template
literal (`\`${code(addr)}\``), which coerces via `String()` → `[object Object]`.
The same mistake was in `/verifybail`'s transaction line and in the restriction
notice's fine/warning lines (`restrictionService.ts`).

**Changes.**

- Removed the `payments` category (`payments:fines`, `payments:bail`) from
  `helpTree`; added `user:jailed` titled "Jailed? (Fines & Bail)" under `user`,
  leading with `/mystatus` and the pay/verify path, then the internal-wallet
  (`/payallfines`, `/payfine`, `/payfines`, `/verifypayment`) options.
- `jail.ts` `/paybail` and `/verifybail` messages rebuilt as single `fmt`
  templates so `code(...)` renders. `restrictionService.ts` fine/warning
  snippets now built with `fmt`.
- New `tests/unit/paybail.test.ts` regression test asserts the reply contains
  the payment address and not `[object Object]`.
- `helpTree.test.ts` / `helpDocumentation.test.ts` updated for the removed
  category and new section.

**Doc-Impact.** `interactive-menus.md` unchanged (menu mechanics unaffected).
README section headings still match the live commands; no text change required.

**Verification.** `bun run lint`, `bunx tsc --noEmit`, `bun run test` (207
passing) green.

## 2026-10-05 — Unify fines into a single bail amount (logic consolidation)

**Decision.** Fines and bail stored two different amounts for the same event: a
jail's bail in `jail_events` (flat 69.42 or custom) and a per-violation fine in
`violations` (USD-configured). When a restriction auto-jailed, both were
created. Chosen model: **a jail's bail is the single payable amount**;
violations remain warning history only, and non-jailed violations charge
nothing.

**Changes.**

- Deleted `src/commands/payment.ts` (392 lines). `/payfine`, `/payfines`,
  `/payallfines` now alias the bail instructions; `/verifypayment <txhash>`
  aliases `/verifybail`. All registered in `src/commands/jail.ts`; `bot.ts`
  drops `registerPaymentCommands`.
- Extracted shared `sendBailInstructions` / `verifyBailPayment` in `jail.ts`;
  both `/paybail` and `/verifybail` and their aliases use them. Release path is
  now one code path (`recordBailPayment` + `releaseMember`).
- `violationService.ts` trimmed to `createViolation` only; removed
  `getUnpaidViolations`, `getTotalFines`, `markViolationPaid`, `VIOLATION_SELECT`
  (no longer payable).
- `/mystatus` drops the separate "Unpaid Fines" total, shows a violation count;
  `/violations` drops payment status and the `/payfine` hint; `/stats` drops the
  unpaid/paid fine lines; restriction responses no longer advertise a payable
  fine; `/customjail` output says "Bail".
- Help/README terminology standardized on "bail"; `/help` → User → "Jailed?"
  documents the bail flow and the legacy aliases.

**Doc-Impact.** Updated `README.md` ("Bail and Verification" section,
`/customjail` wording). `interactive-menus.md` still accurate. `logs` updated.

**Known leftovers (not removed; flag for follow-up).** The owner fine-config
system (`/setfine`, `/listfines`, `/initfines`, `fine_config`, per-restriction
`fine_amount`/`auto_jail_fine`) now only feeds the historical violation amount
and is effectively vestigial. Removing it touches owner commands and schema, so
it was left in place.

**Verification.** `bun run lint`, `bunx tsc --noEmit`, `bun run test` (207
passing) green.

## 2026-10-05 — Remove fine configuration; fixed 69.420 bail; admin reserve bail

**Decision.** All fines/bails are the same fixed amount: 69.420 JUNO
(69,420,000 ujuno), read from `config.defaultJailBailAmount`. Fine
configuration is gone. An admin/owner can additionally release a jailed user by
covering the bail from `SYSTEM_RESERVE (-2)` — never a game/escrow account.

**Changes.**

- Deleted `src/commands/fineConfig.ts` (`/setfine`, `/listfines`, `/initfines`,
  `/customjail`); kept `/junoprice` in new `src/commands/price.ts`
  (`registerPriceCommands`). `bot.ts` updated.

  `getAllFineConfigs`, `usdToJuno`, `calculateBailAmount`,
  `calculateViolationFine`, and the `FineConfig` type. Price display/history
  remain.
- `JailService` dropped the dead `calculateBailAmount`/`calculateBailAmountSync`.

  `config.defaultJailBailAmount` instead of a computed fine; `addrestriction`
  lost its `[jailFine]` argument.

## 2026-10-05 — Consolidate on-chain verification primitives (safe subset)

**Problem.** Four REST/RPC fetchers and three amount-comparison styles overlapped.
Two paths are intentional — the automated deposit listener (RPC `tx_search`) and
the explicit-hash backup (`/verifybail`, `/verifyratelimitreset`, `/checkdeposit`,
`/verifydeposit`, `/claimdeposit`) — but their low-level parsing was duplicated.

**Changes.**

- New `src/services/cosmosRestService.ts`: `fetchTransaction` (shapes REST
  `tx_response`), `findMsgSend` (first ujuno `MsgSend`, optional recipient and
  exact-amount filter), `fetchBalanceMicro`. Fails closed on a missing `code`.
- `JunoService` rewritten on it: `verifyPayment` (unchanged strength — status 0,
  signed `MsgSend` messages, treasury recipient, exact micro, scans all
  messages), new `inspectTransaction` (replaces `UnifiedWalletService.verifyTransaction`
  for `/checkdeposit`), `getBalance` (still null on failure).
- `LedgerService.getSysBalance`/`reconcileBalances` and
  `UnifiedWalletService.getStats` use the shared balance reader; removed the
  now-unused `apiEndpoint` fields.
- `RPCTransactionVerification.parseRPCTransaction` and
  `UnifiedWalletService.findTransferTo` pair repeating `transfer`-event
  attributes by index instead of first-match — fixes multi-transfer attribution
  in both the backup and automated paths.
- Memo handling untouched: REST `body.memo` for the explicit path, `parseMemo`
  for the automated listener.
