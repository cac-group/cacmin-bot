## 2026-10-09 — Rejoin cooldown (pause + buy-out) and membership events

**Cooldown.** Members who leave and rejoin are muted for
`REJOIN_COOLDOWN_SECONDS` (default 1h). The mute pauses while away — owed time
is frozen and one more interval is added per rejoin. State lives in
`user_rejoin_cooldowns` (`pending`, `remaining_seconds`); the live restriction
is an ordinary `muteMember(..., "cooldown")` row, so the message filter and mute
cleanup enforce/release it unchanged. Driven only by the `chat_member` update
path to avoid double-counting joins. Admins/owners/whitelisted are exempt;
first-ever joins and `0` config are no-ops. Migrations 015.

**Buy-out.** Each active cooldown opens/extends a `jailings` row with
`reason = 'rejoin_cooldown'` at the flat `DEFAULT_JAIL_BAIL_AMOUNT`, so
`/paybail`, `/verifybail`, and the deposit listener release it unchanged.
`JailService.payJailing` calls `clearOnBuyout` so the debt does not survive the
payment; `/mystatus` and `/paybail` are cooldown-aware.

**Membership events.** Migration 016 adds append-only `user_membership_events`
(join/leave, chat, source, timestamp), recorded with the `chat_member`
transitions. Bot-owned, no FK (durable history); consumers read only, never
write. Leave handling ensures a `users` row first so an FK error cannot drop the
event.

**Review fixes.** Buying out a cooldown no longer clears an unrelated concurrent
jail: on rejoin a cooldown is skipped when another mute/jailing is active, a real
jail cancels any open cooldown jailing (`cancelOpenCooldown` from
`JailService.jailUser`), a jail starting during the mute-apply await is caught by
a post-await re-check, and the mute row is kept until `releaseMember` restores
the real permissions. Member tags are now applied only on the `chat_member`
path, so a join delivered as both a message and a `chat_member` update tags
once. The unused membership-event index was dropped.

**Museum surface.** telegram-chat-explorer reads `user_membership_events` from
this DB read-only (`CACMIN_BOT_DB_PATH`) and shows join/leave counts on its
per-user view; that change lives in the explorer repo with its own docs/tests.

**Root cause found (mute inactive in production).** The running bot in the
`tgbot` container was the 2026-10-06 build, which predates this feature
(`rejoinCooldownService` absent, migrations stop at 014) — it was never
deployed. Separately, even the new code would not have fired: the
`chat_member` handler in `registerIdentityBlockModeration` did not call `next()`
and is registered first, so it silently stopped the membership `chat_member`
handler (all 192 recorded joins came from `new_chat_members`, none from
`chat_member`). Fixed: the identity-block handler now passes through, and the
cooldown/leave/event logic runs on both the service-message and `chat_member`
paths, with the event log collapsing duplicates.

**Redesign (leaves are not delivered).** Requiring a leave event was the wrong
model: a join for a user we already know is necessarily a rejoin. The cooldown
now triggers on the join (`users` row exists before the join), `recordMemberLeave`
is best-effort for pausing, and `user_rejoin_cooldowns.last_join_at` (migration
017) collapses the same join delivered as both a service message and a
`chat_member` update. If the leave is never seen, the still-running mute supplies
the remainder at the next rejoin.

**Verification.** `bun run lint`, `bunx tsc --noEmit`, `bun run test`
(274 passing, incl. an end-to-end membership-handler test) green.

**Doc-Impact.** New `dev-docs/rejoin-cooldown.md`; README index updated;
`.env.example` gains `REJOIN_COOLDOWN_SECONDS`; `chat-explorer-integration.md`
notes the bot-owned read-only membership event log.
